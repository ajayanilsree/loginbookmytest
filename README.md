# BookyMyTest Details Form

A lightweight, responsive HTML/CSS/vanilla JavaScript page for collecting a customer's name and code. Submissions go through a Vercel Serverless Function and are stored in Supabase PostgreSQL.

## Stack

- HTML5, CSS3, vanilla JavaScript
- Vercel Serverless Functions
- Supabase PostgreSQL via `@supabase/supabase-js`

## Supabase setup

Run this SQL in Supabase SQL Editor:

```sql
create table public.customer_details (
  id bigint generated by default as identity primary key,
  name text not null,
  code text not null,
  created_at timestamptz not null default now()
);

alter table public.customer_details enable row level security;
```

No public insert policy is required. The server function uses the service role key.

If an existing table still has an `address` column, rename it with:

```sql
alter table public.customer_details
rename column address to code;
```

## Environment variables

Create `.env.local` for local development (never commit it):

```env
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-server-only-service-role-key
```

For Vercel, add the same two variables under Project → Settings → Environment Variables. Never expose the service role key as a public/browser variable.

## Run locally

1. Install dependencies: `npm install`
2. Install Vercel CLI if needed: `npm i -g vercel`
3. Run: `vercel dev`
4. Open the local URL and submit a test record.

## Deploy to Vercel

1. Import this project into Vercel (or run `vercel` from the project folder).
2. Add `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` to the Development, Preview, and Production environments as appropriate.
3. Deploy with `vercel --prod`.
4. Test the form on the production URL.

## Admin access

View submissions in Supabase → Table Editor → `customer_details`. The table contains `id`, `name`, `code`, and `created_at`; records are not exposed through a public listing route.

## Testing checklist

- Valid name and code: returns HTTP 201 and shows the success message.
- Blank or over-limit values: rejected in the browser and again by the API with HTTP 400.
- `GET /api/submit`: returns HTTP 405.
- Invalid database configuration: shows a safe generic error; details are logged server-side only.
- Rapid repeated clicks: prevented while the request is in flight.
- Honeypot-filled requests: acknowledged without inserting a record.
